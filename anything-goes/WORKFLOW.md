# OHLUCINDA / Anything Goes 制作・公開基準
更新日: 2026-10-12

この文書は、どのナギ（ChatGPT担当者）でも、作品を追加・更新するとき同じ処理を再現できるようにするための実務ルール。現行のGitHub実装を基に記述する。

## 1. 最優先の原則

- サイト: https://ohlucinda.com/
- GitHub: `ohlucinda/ohlucinda-dtp`、通常の作業対象は `main`。
- Anything Goes: `anything-goes/index.html`。
- **共通ナビの横位置・高さはOHLUCINDAトップページ（`/index.html`）を絶対基準にする。** 「右寄せなら十分」ではない。特にHOMEリンクの**文字の右端**が、トップページを基準にした他のページの右端と揃うこと。上からの高さも揃える。
- HOMEは基準ページであり、基準合わせのためにHOME自体を勝手に改変しない。
- 指示されていない文字、デザイン、画像、記事、リンク、他ページを変更しない。修正を局所的にして、CSSの相互干渉にも注意する。
- コード保存と、公開URLでの見た目・動作の確認は別工程。目視未確認なら未確認と伝える。

## 2. Anything Goesの共通ナビ

作品ビューア上部の順序は必ず次:
**Anything Goes　日本語 / English　HOME**

- `Anything Goes`: 作品一覧へ戻るボタン。
- `日本語 / English`: 同じ作品の言語切り替え。
- `HOME`: OHLUCINDAのホームページに戻るリンク。最後（最右端）。
- フォント: `'adobe-caslon-pro', Georgia, serif`、通常400、**14px、line-height: 1.5、letter-spacing: .02em**。原則、ナビ全要素で統一。
- ナビ内の切り替えの間隔: デスクトップ `gap:9px`、幅560px以下 `gap:6px`。
- `Anything Goes` と言語群の間隔: 20px、幅560px以下は12px。
- HOMEの左側にも20px、幅560px以下は12pxの余白を設ける。ただしCSSの `order` とDOM順の両方を点検し、**HOMEと日本語がくっつくことを絶対に防ぐ**。
- 現行のビューア実装では `#back` をorder 0、`.langs` をorder 1、`.viewer-home-return` をorder 2とする。HOMEは最後。
- ナビ位置の元になるトップページ側: `.frame{max-width:1190px;margin:auto;padding:0 clamp(22px,5vw,76px)}` と `.mast{padding:30px 0 23px}`。幅800px以下では左右 `clamp(18px,4vw,32px)`、640px以下では20pxの指定がある。**最終的には実際のHOMEと現行CSSを再確認すること。**
- Anything Goes の `viewer .toolbar` に `--ohl-nav-edge` を使った右端計算がある。CSSには過去の上書きルールも残るため、**最後に実際に効くCSS**を確認してから修正する。
- 同じビューアを全作品で使う。個々の記事内に別ナビを勝手に作らない。

## 3. フッターの共通ルール

- `© OHLUCINDA`: **14px**。
- `GET IN TOUCH`: 存在するページは**14px**。リンク先を変えない。
- Anything Goesの作品ビューアでは `© OHLUCINDA` をビューア下部に表示。作品表示領域を邪魔しない。
- フォントや配置の既存仕様は守る。サイズ統一を理由に別要素まで変更しない。

## 4. 記事ページのタイポグラフィ基準

**日本語版と英語版でタイトル・本文のフォントサイズを必ず同じにする。** デスクトップだけでなく、媒体幅に応じたCSS、メディアクエリ内の指定も全部照合する。

現在の「泡の意味」「シーツの記憶」で揃えている共通値:

| 対象 | 指定 |
|---|---|
| タイトル `h1` のサイズ | `clamp(25px, 3vw, 34px)` |
| タイトルの太さ | `font-weight: 500` |
| タイトルの字間 | `letter-spacing: .08em` |
| 本文のサイズ | `clamp(15px, 1.35vw, 18px)` |
| 本文の字間 | `letter-spacing: .035em` |
| 本文の行間（基本） | `line-height: 2.15` |
| タイトル下余白（基本） | `margin-bottom: 5rem` |

**フォント種類（記事の現在の基準）**:
```css
font-family: -apple-system, BlinkMacSystemFont,
  "Hiragino Sans", "Yu Gothic", "YuGothic", sans-serif;
```
これはフォントの候補順であり、すべてのOSで同一の字形を保証するものではない。本文は親から継承し、タイトルも同じファミリーを使う。日本語・英語の間で勝手にフォントを分けない。

### 記事ごとのレイアウト例外

- **泡の意味**: 幅820px以下で `h1` は `clamp(20px, 2.8vw, 28px)`、本文は `clamp(15px, 1.35vw, 18px)`。この例外も日英同じにする。本文の行間は2、タイトル下余白3.6rem。金魚と文章は左右分割を保つ。
- **シーツの記憶**: 幅620px以下は記事幅82vw、本文の行間2.05、段落下余白2.7rem。タイトルと本文のフォントサイズは基本値のまま。背景のグラデーションは日英一致。
- 既存記事の作品固有の背景・画像・余白・レイアウトを、共通化のために消さない。**共通化するのは文字の種類と大きさ、および言語版どうしの対応部分。** 例外的な変更は指示がある場合だけ。
- Anything Goes「作品一覧」のタイトル・作品名のスタイルと、「作品本文」のタイトル・本文のスタイルは別物。混同しない。

## 5. 作品の追加手順（新しい記事を渡されたとき）

1. **受け取った日本語HTMLを確認**。文章、改行、段落、背景、画像、レスポンシブCSSを正確に把握する。ユーザー指定の改稿を優先し、本文を独断で編集しない。
2. **英語原稿が添付されていたらその原稿をそのまま使う。** 英語原稿がなければ、翻訳の必要性と扱いを確認する。タイトルの訳も独断で固定しない。
3. 各作品は `anything-goes/<slug>/index.html` と `anything-goes/<slug>/en/index.html` に置く（例: `awa-no-imi`, `sheets-memory`）。
4. 日英HTMLの背景、画像、構図、h1/本文のフォント種類・サイズ・太さ・余白・行間・文字間隔とメディアクエリを**項目ごとに照合**する。作品固有の意匠は保ち、日英で一致させる。本文言語と `<html lang>`、`<title>` は適切に分ける。
5. `anything-goes/index.html` の `<main class="collection">` に新しいカードを追加。既存の順序を壊さず、作品番号 `Words · 0N`、日本語名、英語名、説明、サムネイル用のアート指定を設定する。勝手な紹介文を作品内容に断定的に付けない。
   **サムネイルはナギが制作する。** 既存のAnything Goesのサムネイルをユーザーは気に入っているので、新作でもその雰囲気・色彩感・抽象性・一覧に並んだときの統一感を大切にして制作する。毎回同じ絵柄にする必要はなく、作品ごとの個性を出しながら、Anything Goes全体の空気に自然になじませる。既存サムネイルを確認してから作り、ユーザーから変更希望があればそれを優先する。
6. ビューアJSで新作の識別子を扱う。現行では `openWork`、`show(l)`、`workUrl`、`restoreWorkFromUrl`、`renderArtwork` 等を確認する。作品カードのクリック、`?work=<slug>&work_lang=ja|en`、言語切替、戻る、履歴、再読み込みに対応させる。
7. ビューアは作品HTMLを `fetch` してiframeへ描画する方式。両言語のパスが正しいか確認する。既存の「色を食べる」「泡の意味」などのルートを壊さない。
8. **共通ナビを検証**。「Anything Goes　日本語 / English　HOME」の順序、文字間隔、HOME右端と高さのHOME基準への一致を、幅の異なる画面で確認する。
9. **全言語・全記事のリンクと見た目を確認**。一覧、日英切替、直接URL、フッター、スクロール、スマホ幅、404がないことを検証する。
10. GitHubへ保存後、変更したファイルと確認できた範囲を正確に報告。**保存しただけで「公開画面確認済み」とは言わない**。

## 6. 既存記事の差し替え・修正

- 「本文の文字サイズだけ」なら該当する本文CSSとモバイルCSSのみ変更。タイトルや文章や画像は変えない。
- 「タイトルのサイズだけ」なら見出しCSSのみ変更。
- 一方の言語の文字サイズを変更したら、**もう一方の言語も必ず照合し、統一を求められているなら同じ指定にする**。
- 新しいHTMLを渡された場合、現在のHTMLとの差分を確認する。画像がbase64で埋め込まれている場合、無関係な画像データを再生成・改変しない。
- 公開先へのパスと既存のリンク構造を維持し、他の記事に影響させない。
- `!important` の積み重ねだけで解決を決めつけない。既存競合を把握して最小変更する。

- [ ] 指示された原稿・改稿が正確に入っている
- [ ] 日本語版と英語版が同じ意匠、フォントファミリー、タイトルサイズ、本文サイズ
- [ ] PC幅・狭い画面幅の両方を照合
- [ ] Anything Goesの一覧に表示される
- [ ] 日本語 / English が各作品の正しい版に切り替わる
- [ ] URL直打ち、再読み込み、戻るが機能する
- [ ] HOMEと日本語はくっついていない、HOMEは一番右
- [ ] HOMEリンクの**右端と高さ**がトップページのナビ基準に合っている
- [ ] © OHLUCINDAは14px。GET IN TOUCHのあるページは14px
- [ ] 他作品や他ページに意図しない変更がない
- [ ] GitHub保存と公開画面での実確認を区別して報告する

この基準は**今後の作業指示書**であって、これ自体が既存全ページの表示の一致を証明するものではない。実際の表示確認をして合致を確かめること。
