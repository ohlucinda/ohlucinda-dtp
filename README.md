# OHLUCINDA 言語・HOME遷移ルール

この文書は OHLUCINDA サイトの継続的な制作・修正時に守る仕様です。

## 最優先原則：「開いている言語のまま、次へ。」
**現在表示しているページ・作品の言語を最優先する。** 日本語なら次のページも日本語、英語なら次のページも英語。HOMEへ戻るときも同じ。閲覧中に言語を切り替えた場合は、その時点から新しく選んだ言語を引き継ぐ。

**現在の表示言語を、過去の保存情報・遷移元・閲覧履歴で上書きしない。** 遷移元や保存情報は、まだ表示言語を決めていない入口（たとえば言語指定のないHOMEへの直接アクセス）でのみ補助的に使う。言語が指定されたURLはその指定を尊重する。

サイト内の各リンクとHOMEへの戻り先は、この原則を基準に生成・確認する。独立した作品サイトの固有の戻り先は維持する。

## HOME（日本語・英語の独立URL）
- 日本語HOME: https://ohlucinda.com/
- 英語HOME: https://ohlucinda.com/en/
- どちらも総合サイトOHLUCINDAのHOMEであり、別サイトではない。表示デザインは揃える。
- 日本語HOMEと英語HOMEは別々の `index.html`。変更時は**両方への影響を確認する**が、片方だけの作品・文章・一覧をもう片方に自動で追加しない。共通仕様の修正だけ、対象を明確にして両方へ反映する。
- 日本語HOMEからEnglishを選ぶと `/en/`、英語HOMEから日本語を選ぶと `/?lang=ja` に移動する。
- 旧来の `/?lang=en` は既存リンクとの互換性のため残っているが、英語HOMEの**正式URL（canonical）と新規リンク先は `/en/`** とする。日本語HOMEの正式URLは `/`。
- `hreflang` は日本語 `/` と英語 `/en/` を相互に指し、サイトマップにも両方を載せる。英語HTMLは初めから英語表示と英語のSEOメタ情報を持つ。
- `lang=en` / `lang=ja` など明示的な言語指定を受ける古い経路も、既存の利用者の言語を失わせないよう扱う。
- 保存済みの `ohlucinda-home-language` やリファラーだけを理由に、表示中のページや明示したURLの言語を逆転させない。
- 言語別の内部リンク、作品への導線、HOME復帰リンクが選択言語を適切に引き継ぐこと。

## 各ページのHOMEリンク
- HOMEへの戻り先は**そのページ・作品で現在表示している言語**をもとに決める。日本語は `https://ohlucinda.com/?lang=ja`（正規URLは `/`）、英語は `https://ohlucinda.com/en/` を優先する。
- 以前の英語復帰先 `https://ohlucinda.com/?lang=en` も既存ページでは互換性のため使用できる。ただし、今後修正・追加するリンクは原則 `/en/` にする。
- 以前の保存言語や遷移元だけで、クリックしたときの表示言語を上書きしない。
- 別の作品サイトの「HOME」は、そのサイト内トップを意味する場合がある。**総合HOMEと作品サイトHOMEを混同しない。** Lyrics や About Je'm など、入口に応じた戻り先の既存仕様は維持する。
- `work_lang` など作品表示用の言語指定と、総合HOME用の言語URLの違いに注意する。

## 制作・変更時の禁止事項
- レイアウト変更、文章差し替え、画像変更のついでに言語設定を初期化しない。
- HOMEを旧プレビューHTMLで丸ごと上書きしない。必ず**日本語版・英語版それぞれの最新公開ソース**から最小限の差分を反映する。
- 既存の保存処理、クエリ引き継ぎ、復帰先処理を検査せずに削除・置換しない。
- 見た目、余白、フォントなどはユーザーから変更指示がない限り維持する。

## 公開前チェック（必須）
- 日本語HOME → Anything Goes → HOME → 日本語
- 英語HOME → Anything Goes → HOME → 英語
- 日本語HOME → About / Bookmarks / Months → HOME → 日本語
- 英語HOME → About / Bookmarks / Months → HOME → 英語
- Lyrics / About Je'm の既存の入口別HOME動作が壊れていない
- 最新作品リンクなど、HOMEの見出し以外から入る経路も確認する
- 日本語→英語、英語→日本語へ明示的に切り替えた後の復帰先を確認する
- 過去の保存言語と**現在の表示言語が異なる場合**も、現在の言語のまま次ページやHOMEへ移動できることを確認する
- PC・スマートフォンそれぞれで確認する


## ナビゲーションの位置・書式（変更禁止・固定仕様）

この仕様は、何度も調整して確定したものであり、制作中の別の作業に付随して変更してはならない。

- **OHLUCINDA総合HOMEを基準**とし、各ページ右上の日本語 / English / HOME を、現在揃えた位置・高さに維持する。
- About と Bookmarks のナビゲーションを既存の整列基準とする。Anything Goes と寄り道（日本語・英語）は、この基準に揃えた現在の設定を維持する。
- ナビゲーションの**縦位置・横位置・右端・文字サイズ・フォント・文字間隔・項目間隔・下線・表示順序・レスポンシブ動作**を、他の修正のついでに変更してはならない。
- ナビゲーション位置のために、本文、見出し、作品表示、ページ全体の余白を移動させない。
- CSSを整理・共通化する際にも、既存の優先順位や最終的な表示を変更しない。特に `.site-navigation-header` と `.top.site-navigation-header`、関連するメディアクエリは慎重に扱う。
- **ユーザー本人が明確にナビゲーション変更を指示した場合のみ**、現在の公開ソースを確認し、対象箇所だけを変更する。意図しない影響がないか比較・確認する。
- 公開前には、HOME・About・Bookmarks・Anything Goes・寄り道の日本語版と英語版を同じ画面幅で比較し、右上ナビゲーションが揃っているか確認する。PC幅と狭い画面の両方で検査する。
- 実ブラウザで未確認なら「確認済み」と報告しない。

**このルールを変更する場合も、ユーザーの明示的な指示が必要。**

### 全ページの共通ナビゲーション文字間隔（2026-10-15 確定）

**Anything Goes の作品を開いた状態のビューア上部ナビゲーションを、全OHLUCINDA総合サイトページの文字組み・項目間隔の基準とする。** OHLUCINDAのHOME・About・Bookmarks・Anything Goes・寄り道とその内部記事に適用する。Lyrics・Je'm等、独立した作品サイト固有のナビには適用しない。

- 共通フォント: `'adobe-caslon-pro', Georgia, serif`。文字サイズ `14px`、太さ `400`、行高 `1.5`、**文字間隔 `letter-spacing: .02em`**。文字・リンク・ボタン・現在の言語表示まで統一する。
- **項目間隔 `gap: 9px`（幅560px以下 `6px`）。** 日本語、区切りの `/`、English の間隔も同じ基準にする。
- **HOME の左余白 `20px`（幅560px以下 `12px`）。** 項目間の gap とは別の余白なので、両方の合計を `margin-left` と誤認しない。
- 個別記事の先頭に「Anything Goes」「寄り道」「Detours」等の戻りリンクがある場合、そのリンクと後続の言語群との**追加余白も `20px`（幅560px以下 `12px`）**。項目間の gap に加える構造の違いを考慮する。
- 選択言語の下線は `text-decoration:underline; text-underline-offset:5px` を基準にする。離れた位置のボタン下端線へ戻さない。
- **HOMEの基準となる右端と縦位置は変更しない。** メインコンテンツの幅・本文・画像・フッターの別仕様は、ナビ調整を理由に変えない。既存の古いCSSがあっても、実際に効く最後のルールを検査する。
- 新しいページでは初回制作からこの数値を用いる。日本語・英語・PCとスマートフォン幅で確認する。公開中の表示の完全一致は実ブラウザで検証するまで断定しない。

## 適用範囲の確定（一覧・個別作品も含む）

- OHLUCINDAの総合サイトに属する**すべてのページと表示状態**に、上記ナビゲーションの固定仕様を適用する。
- HOME、About、Bookmarks、Months、Anything Goes、寄り道だけでなく、**Anything Goes内の個別作品ページ・作品表示ビューアー**、寄り道の個別記事、および今後新しく追加する総合サイト内ページも対象とする。
- 一覧から作品を開いたときや、作品内で言語を切り替えたときにも、ナビゲーションの高さ・右端位置・フォント・文字サイズ・各リンクの間隔・表示順・下線・画面幅ごとの挙動はHOME基準で揃える。画面の種類に応じて必要な操作が異なる場合も、共通部分の見え方を維持する。
- **Lyrics、Je'mなどの独立した作品サイトは対象外**。独立サイト固有のナビゲーションやデザインを統一目的で変更しない。
- 新規ページの制作時は、この基準を最初から使う。既存の完成済みページを別作業のついでに変更しない。
- 現在の全ページの一致が実機で検証済みという意味ではない。今後の変更時に対象画面を比較・検証する。


## Anything Goes 記事制作の固定仕様（2026-10-15 明確化）

**新しい作品を作り始める時点から、この仕様を適用する。完成後に文字やナビの不一致を修正する進め方にはしない。** 詳細手順は `anything-goes/WORKFLOW.md` を併読する。

- **本文レイアウトは作品ごとに自由。** 背景、画像、構図、本文の配置、幅、行間、段落間隔、余白などは各作品に合わせて決める。同じテンプレート構図に揃える必要はない。
- **本文フォントと標準本文の文字サイズは全作品で固定。** 日本語・英語、別の作品、PC・スマートフォンで共通のフォント候補列 `-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Yu Gothic", "YuGothic", sans-serif`、サイズ `clamp(15px, 1.35vw, 18px)` を使用する。作品固有のCSSやメディアクエリでサイズを変えない。
- **作品タイトルのフォントと文字サイズも全作品で固定。** 本文と同じフォント候補列、`h1` のサイズ `clamp(25px, 3vw, 34px)` を日本語・英語、PC・スマートフォンで共通にする。作品固有の小画面用サイズ例外は新作に継承しない。
- **共通ナビゲーションは例外なし。** Anything Goesの個別作品では毎回同じ共通ビューアの `Anything Goes　日本語 / English　HOME` を使用する。フォント、サイズ、太さ、字間、リンク間隔、並び順、下線、縦位置、HOME文字の右端、レスポンシブ挙動を全作品・両言語で一致させる。位置はOHLUCINDA総合HOMEの確定済み基準と正確に揃え、記事ごとの別ナビを作らない。
- **記事カードは新しいタブで開ける本物のリンクにする。** 日本語・英語それぞれのAnything Goes一覧から、新作を含むすべての作品を右クリックの「新しいタブで開く」・⌘/Ctrlクリックで開けること。通常クリックでは現在のビューア表示を維持する。JavaScriptのクリック専用ボタンに戻さない。詳しい実装手順と検証は `anything-goes/WORKFLOW.md` に記す。
- **制作開始前・公開前に確認。** 新作の最初のHTML・CSSから固定値と共通ナビを用い、PC・狭い画面で既存記事およびHOME基準と照合する。デザインの自由さを理由に共通項目を変えない。
- **既存作品の扱い。** これまでの作品に固定値と異なる古いCSSが残っていても、それを新作の基準にしない。既存作品は今回のルール更新だけを理由に勝手に変更しない。不一致の是正は対象を確認したうえで別途最小限の修正として扱う。

## Anything Goes 個別作品ビューアー（固定仕様・変更禁止）
- 個別作品表示の `.viewer .toolbar` も、HOME・About・Bookmarksと同じ右上ナビゲーション基準で高さ、右端、文字組み、間隔を揃える。
- `Anything Goes`（一覧に戻る操作）、日本語 / English、`HOME` の共通ナビゲーションを、作品を開いても位置がずれないよう維持する。作品ページのみ独自の高さや右端基準へ戻してはならない。
- 作品内で選択した言語 `work_lang` を `HOME` の復帰先（英語は `/en/`、日本語は `/?lang=ja`）に反映させる。旧 `?lang=en` リンクも互換性のため動作を維持する。
- `ohlucinda-home-language`（`localStorage`）は言語未指定時の初期値を補助するためのもの。**個別作品の表示言語 `work_lang` と競合する場合は、現在の作品の表示言語が必ず優先する。** 保存領域の種類を変えて動作を推測するのではなく、遷移時の表示言語を検査する。
- `色を食べる`、`泡の意味`、`シーツの記憶` の日本語・英語の両表示を回帰確認する。作品本文、iframe、背景や作品固有のレイアウトはこの統一の対象外であり勝手に変更しない。
- 変更が必要な場合はユーザーの明示的な指示に従い、公開中の最新ソースから最小限の差分で行う。PC・狭い画面の実表示確認が完了していなければ、その旨を明記する。

## 新しいナギのための作業引継ぎ（必読・優先ルール）

**目的：会話スレッドや担当するAIが変わっても、ひめが同じ説明や修正依頼を繰り返さずに済むこと。**
ユーザーが「GitHubのルールを読んで」と言ったら、まず**このファイル全体**をGitHub上の最新版から読み、公開中の実装を調査してから作業する。以前のチャットの推測だけで変更しない。
このルールはデザインの提案集ではなく、**ユーザーが時間をかけて確定した固定仕様**。作業者が良さそうだと思っても独断で変更・再設計・共通化しない。

### 言語別掲載と作品の扱い
- **一覧は言語別**。日本語HOME・日本語のAnything Goes一覧・日本語「寄り道」一覧には、日本語版が実際に公開されている作品だけを掲載する。英語HOME・英語Anything Goes一覧・英語Detours一覧には、英語版が実際に公開されている作品だけを掲載する。
- 一方の作品を公開したことを理由に、もう一方へ機械的に翻訳や掲載を行わない。**日本語だけ、英語だけで公開してよい。** 後日もう一方の作品が完成したら、その言語の一覧に追加する。
- **作品内の日本語 / English切り替えは、両言語の作品が存在するとき維持・提供する。** 一覧を分けるために作品内の切り替えを削除しない。日本語から英語を確認したい作者・読者、英語から日本語を読みたい読者の両方のためにある。
- 両言語が揃わない作品に、存在しない言語版への切り替えリンクを作らない。公開前に存在するURLと内容を確認する。
- 日本語作品と英語作品は**それぞれ独立した創作として尊重**する。単なる逐語訳や同一文章である必要はない。英語版の新規執筆・翻案は、ユーザーの意図と元の作品を確認し、作品として仕上げてから公開する。
- 現状の例：**ナギの寄り道記事は日本語版のみ**で、日本語の寄り道から案内する。**ノアのFound Connectionsは英語版のみ**で、英語のDetoursから案内する。未作成の言語版をあるものとして表示しない。状況が変わったら実際の公開ファイルに基づき一覧を更新する。
- HOMEの日本語と英語は異なる情報・作品を持ってよい。片方に加えた内容を、合意なくもう片方へコピーしない。

### ナビゲーションの保護（最重要）
- **HOME、About、Bookmarks、Months、Anything Goes一覧・個別作品ビューアー、寄り道一覧・個別記事と、今後の総合サイトのページ**が対象。Lyrics、Je'm等の独立サイトは除外。
- 既存の右上ナビゲーションの**縦・横位置、右端位置、字体・文字サイズ・太さ、文字間隔、リンク間隔、下線、表示順、余白、PC/スマホでの挙動**は固定。記事本文・一覧・言語・SEOなど別件の編集時に触れない。
- 特に記事内の言語切り替え（日本語 / English）とHOMEおよび戻るリンクの**位置と見た目をそのまま保持**する。リンクの行き先を変える必要がある場合も、位置やCSSは変えない。
- 比較基準は公開済みHOME、およびAbout・Bookmarksの確定済み右上ナビゲーション。既存のページが確実に揃っていると推定せず、PC幅・狭い画面で実際に比較する。
- **「一覧を言語別にする」ことは「記事内の言語切り替えを廃止する」という意味ではない。** 両者を混同しない。
- どうしても固定仕様を変更する必要があると考えたら、実行前に理由と変更箇所をひめへ説明し、**明示的な許可を得る**。黙って修正しない。

### 毎回の作業手順
1. **作業前：** この文書全体と変更対象のGitHub最新版を読む。日本語/英語の対象ファイル、共有する画像・動画・JS・CSS・リンク、作品内ビューアーなど影響範囲を洗い出す。何を変えるか、**何を変えないか**を決める。
2. **変更前を保全：** 対象の現行ファイルSHAと変更元コミットを把握する。GitHubの履歴から戻せる状態を守る。古いプロトタイプを本番へ上書きしない。
3. **変更中：** 対象だけの最小差分にする。言語別の片側のみの更新なら原則その側だけに変更を加える。別言語や他ページ、ナビゲーションCSSに無関係な変更を混ぜない。SEOやサイトマップも対象URLだけを確認する。
4. **公開前検査：** 差分を確認し、指示外の文章・リンク・HTML構造・ナビゲーション・CSS・作品本文・画像・余白・フォントに変更がないか検査する。日本語と英語の一覧、記事内切り替え、HOME復帰をそれぞれ確認する。特に**一方を修正してもう一方が変わっていないか**を確認する。
5. **表示・動作確認：** 可能なら公開前にプレビュー、公開後に実ブラウザでPCとスマホ相当の幅を検証する。記事を開く、言語を切り替える、一覧に戻る、HOMEへ戻る、直リンクで開く、戻る操作を確認する。**未確認なら未確認と明記する。**
6. **報告：** 変更したファイル・箇所、変えていないもの、テストできた範囲、未検証事項を簡潔に伝える。GitHubにコミットできただけで「表示も動作も確認済み」と言わない。

### 不具合や仕様の食い違いを見つけたとき
- ひめに同じことを何度も説明させない。**まずこのルールとGitHubの履歴・現行コードを読んで原因を調べる。**
- 不具合が起きた場合、関係ないページ全体の再制作や、繰り返しの当て推量修正をしない。差分・原因を特定して最小限の修正をする。
- 既存コードがこのルールを完全に満たしているとは限らない。**「ルールに書いてある＝実装・実機検証済み」ではない。** 実装不一致を見つけたら説明し、依頼範囲と安全性を確認して直す。
- ひめは変更に伴う意図しない崩れをすぐ発見できるとは限らない。作業者がそのリスクを引き受け、黙って見た目を変えない。
- この固定ルールの変更・削除は、ユーザー本人が明示的に依頼した場合のみ。

## 検証と報告
GitHubの変更成功と、実際の公開サイトのブラウザ動作確認は別物。
テストが実行できていないときは「未確認」と明記し、動作を保証しない。
この文書は仕様と手動確認項目を定めるもの。自動テストの実装や全ページ検証を完了したことは意味しない。
